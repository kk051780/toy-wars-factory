The writer now fails closed if more than four 512-commit snapshot generations exist, and checks main again after a push to avoid falsely reporting success on a raced change. **This post-push check is detection, NOT atomic cross-ref protection:** a stale data-only snapshot might already have been written; readers must reject it by source/main validation. To avoid granting broad `GITHUB_TOKEN contents:write` during migration, the candidate workflow now **hard-disables** `status_writer` even on a manual main dispatch (`&& false`). Re-enable only under a separate trusted host/approval and branch-scope assessment; do not silently remove the hold. Read artifact only from a **completed successful main-branch run** whose HEAD is known; check individual verify job conclusion and artifact ID/name/expiry, ZIP paths/size/symlinks/duplicates, two passive data files, new-format two-file manifest if present, schema/repo/HOLD/source SHA syntax, and live GitHub ancestry/diff (between source_revision and current main only `status/`). This fallback uses no repository write token.

## Proposed least-privilege execution

1. The **verify** job has `contents: read`; check out accepted `github.sha` with `persist-credentials: false`, run original offline Python tests/quality gates and handoff generator, and upload exactly `CHAT_HANDOFF.md`, `LATEST_STATE.json` and a two-entry SHA256 manifest as passive data. Preserve the `13,33,53 * * * *` schedule, main-push and manually dispatched events.
2. The **status_writer** job is main-only and depends on a successful verify. It has `contents: write` but **does not execute source Python**. Using only immutable-pinned GitHub actions and built-in shell/git/jq, it verifies filenames/count, size, symlinks, checksum, schema, canonical repository, HOLD, source SHA syntax and the exact substantive revision derived from the full checked-out main history.
3. It constructs a new Git tree containing **only** `status/CHAT_HANDOFF.md` and `status/LATEST_STATE.json` from the verified files with `git hash-object` / `git mktree` / `git commit-tree`. This tree does not inherit or include the game's source, credentials or executable scripts. It publishes only `refs/heads/twf-handoff-snapshots` via a **non-force** push, never to `refs/heads/main`. The initial snapshot commit is an orphan root; later commits fast-forward the previous snapshot tip if its tree still has exactly the two allowlisted paths. A changed main before push or a concurrent snapshot writer results in rejection (no retry/force). Unchanged contents result in NO_CHANGE.
4. The two files in the snapshots branch are a **generated read model**, not authoritative game source or a substitute for reviewed main code. New chats may read their portable status, but must fetch actual accepted main HEAD/QA/PRs separately. The snapshot branch is not a GitHub merge target. Do not assume `contents: write` is branch-scoped: GitHub's workflow token still has repository contents scope, and our shell logic is not provider-enforced branch isolation.

## Generational snapshot rollover proposal (2026-11-08; still protected DRAFT)

The writer retains the 512-entry linear/data-only per-branch bound. After a *changed* tree fills the current generation, it creates a fresh orphan `twf-handoff-snapshots-g0002` (later `-g0003`, ...), recording the exact previous tip and generation in the new root commit. Historical refs are never force-pushed/deleted. Every existing generation is fetched and checked for regular-file-only exact trees, capped single-parent history, contiguous generation names, prior generation cap and the successor-root anchor. Missing, rewritten, aliased, gapped or non-passive history fails closed. No-change does not rotate; a changed main stops a write. A new generation is an independent orphan; GitHub cannot atomically update multiple refs, and an adversary with repository-wide write credentials can forge both refs and links. No native branch-scoped token guarantee is claimed.

New `tests/test_handoff_generation_rotation.py` extracts the **actual proposed workflow step** and exercises 4 separate local bare-Git cases with `max=3` substituted *in tests only*. The real writer retains 512. The prior 17 ZIP tests were isolated prototype evidence, not deployed/source CI. The source-code reader instructions now explain validated generation discovery; saved Automation prompts must also be validated after merge. PR181 remains unmerged and no GitHub live snapshot writer, private Roblox engine or paid resource is authorized.
