# ChatGPT定期ゲーム修正

ユーザーは2026-10-25、毎回の「進めて」を必要とせず、現在のゲームの修正を
自動で続ける体制を明示的に依頼した。既存の毎時監督タスクを実装担当に変更する。
Geminiの未解決問題を、接続済みGitHubでのChatGPTによるdraft PR作成と混同しない。

## 実行経路

- タスクID: `6adbf0d6a7d881918ce181dff2468867`
- ChatGPT側の既存スケジュールを維持し、1時間ごとに実行。PC常時起動は不要。
- 正本はGitHub。ローカルフォルダが次回も残ることを前提にしない。
- `config/autonomous_repair.json`がmainに存在し、enabled=trueの場合だけ着手する。
- 固定ブランチ`auto/twf-game-repair`、`[TWF auto-fix]`で始まるdraft PRを1本使用する。
- 通常の課題選択、修正、オフライン検査、draft PRの更新には都度の指示を求めない。
- mainへのマージ、外部モデルAPI、課金変更、Roblox公開は別途承認のままとする。

## 毎回の手順

1. main・引き継ぎ・AGENTS・方針・PR・Actions・Issuesを取得し、既存成果を確認する。
2. 自分のPRの未完了作業や失敗CIがあれば先に直す。既に統合済みの修正を再作成しない。
3. 小さな不具合または意味のある実行可能な回帰検査を1件選び、実コードを編集する。
4. 正本のゲームスクリプトを使う検査を追加し、変更・サイズ・原因・次回作業を新しいC履歴へ記録する。
5. GitHubのbase treeを保ち、expected_sha付きでブランチを更新し、draft PRと実際のCI結果を残す。
6. 実行中のCIは次回へ引き継ぐ。長時間ポーリング、監査コメントだけの反復、成果の捏造をしない。

初回はHeartbeatから生産・購入処理を実行する検査を`tests/auto/production_spec.lua`
へ追加する。十分な残高と不足残高の両方を全サーバー経由で検証し、再現した欠陥だけを
最小限修正する。検査コードだけを追加した場合、ゲーム本体を修正したとは報告しない。

## 編集範囲と検査

ゲームの編集は既存Balance・Server・HUDの3ファイル。新しいLua検査は
`tests/auto/*_spec.lua`、新しいPython検査は`tests/test_auto_*.py`に置く。
記録は新規`history/CNNNNN_*.json`と`docs/EXPERIMENT_LOG.md`。
既存テスト・ハーネス・品質方針・ワークフロー・認証・モデル設定は変更しない。

自動修正PRではbaseの検査スクリプトと方針を使い、許可範囲外の差分、既存回帰検査の
書換え・削除、検査なしのゲーム変更、監査記録だけの差分を拒否する。
これは変更範囲の検査であり、GitHub接続権限そのものをファイル単位で制限する仕組みではない。

既存の27サーバーケースと6 HUDケースは固定のnegative controlを持つため変更しない。
追加Lua検査をCIが自動発見して実行し、失敗を成功扱いにしない。ログを
`twf-autonomous-regressions-not-engine`へ保存する。既存のLua/Python・コンパイラ・
インストーラ・サイズ履歴・引き継ぎの検査も残す。

## 登録と成功の区別

タスク更新が成功しても、自動コード修正が成功したとは判定しない。
初回のサービス実行記録、実際のGitHubコミット・draft PR、対応するCIを別々に照合する。
登録時の`first_run_verified=false`は初回試験の証拠が出るまで維持する。
定期処理の有効表示だけで24時間の安定稼働を主張しない。

Gemini試行・独立レビュアーの直接API通信は停止を継続する。自動マージの承認条件や
Roblox実機・複数人・スマホ検証は免除しない。ChatGPTの接続・利用上限で止まった場合は、
具体的な不足を報告する。追加の契約や購入で自動解除しない。
