# EGG RAID RUMBLE｜プレイヤーLv・試合内成長・装備熟練度

企画室 IDEA_CARD P0D-STUDIO-PLAYER-LEVEL-MASTERY-001 / Issue #281 / 2026-11-13 JST。

**現在の成果は実際に実行可能な純Luauルールのみ。** #275の無料孵化・所有/装備と#280の実物3D魔獣能力、#279のCLASSIC/SCORE選択は別の担当。既存のH1 Game/Remote、公式RC、DataStore、課金、公開は変更しない。現時点で実ゲームにXP UIや永続化は存在しない。

## 独自の楽しい成長循環

- **プレイヤーレベル1〜50：** Lv1→2の必要60XP、以降の次レベル必要XPは60+40×(現Lv−1)。卵取得などの一つの有効行動と、60秒以上の正規試合終了で初戦Lv2に到達可能。Lv50累積49,980XP。プレイヤーが負けても正規参加の基本報酬がある
- **試合内フォーカス1〜3：** 試合中の貢献25ポイントでLv2、60ポイントでLv3。毎試合リセット。将来の「中央の卵の方角を短く知らせる」「護衛ルートを表示する」などの情報選択の前提であり、当面HP・攻撃・移動速度や権威の変更は一切なし
- **実際に使った魔獣・装備の熟練度1〜10：** 6カテゴリ（魔獣・魔法・乗物・武器/道具・ゾンビ・罠）共通。所有と装備を検証したアイテムの本物の使用1試合1回だけ熟練度+12XP。Lv3は色違い、Lv6はモーション、Lv10は称号。基本能力自体をレベルで封鎖しない
- **名誉・収集報酬：** プレイヤーLv2歓迎バナー、Lv5巣飾り、Lv10エモート、Lv20乗物の軌跡、Lv30城旗、Lv50オーラ。無課金の自己表現であり勝率上昇の固定能力ではない
- **無料孵化との結合:** 「卵を得点につなげる→試合後無料孵化→OWNED/EQUIPPED→次戦で実使用→熟練度が上がる」という目的。だが今のLuauはXP算出のみ、#275/#280がまだ実ゲームと連結されていると偽らない

## サーバー承認行動の暫定XP案

| 有効なゲーム内の貢献事実 | XP | 1試合計数上限 |
| --- | ---: | ---: |
| 正規に卵を取得 | +10 | 2 |
| 正規に卵を城に納入 | +25 | 2 |
| 正規に奪還 | +20 | 1 |
| 正規の護衛支援 | +10 | 2 |
| 正規の防衛支援 | +10 | 2 |
| 所有・装備した魔獣/装備の正規発動 | +12 | 1 |
| 60秒以上で貢献がある試合終了 | +50 | 1 |
| 勝利ボーナス | +15 | 1 |
| 引分ボーナス | +5 | 1 |

**1試合上限は150XP。** 正規試合終了まで獲得は確定しない。装備の発動だけでは試合終了XPをもらえない。負けたチームでも貢献すれば経験値が入るため初心者や守備役が冷遇されない。長時間放置、ダメージ・キル稼ぎ、同じ卵の高速出し入れ、クライアント側のイベント偽装ではレベルを上げられないよう、取得元は必ず既存Gameが確定する。毎回の正規行動IDは試合内重複拒否、種類ごとの回数上限もある。

## 役割別のレベルアップ体験

**RAIDER（奪取役）** は拾って届けることが自然な経験値源。**GUARDIAN（守備役）** は卵の奪還・護衛・防衛で経験値を得られる。勝ちだけを追うとチーム貢献より倒す行為が得になることを避ける。

試合内フォーカスLv2/3で新たな選択を表示する場合も、最初は仲間に役立つ情報・見た目・戦術の横展開とし、敵のHP・速度・ダメージに直接の永続バフを付けない。

**初回プレイ案:** 10秒程度で卵を目撃→60秒以内に一度貢献→試合終了で「+60 XP → Lv2!」の明瞭な喜び→無料孵化と装備→次戦で使って熟練度+12。経済化より先に2試合目に本当に戻りたい気持ちを実測する。

## 技術と未実装ゲート

実装はソース P0D-PROGRESSION-XP-MASTERY-20261113-01/src/ProgressionRules.luau だけ。サーバーからのイベント種別・正規で一意のeventId・ゲームJobID付きroundId・userId・CLASSIC/SCORE種別・サーバーが確かめた所有/装備事実を入力とする。Gameがイベントを検証する前にクライアントのXP要求を受ける仕様は禁止。

newProfile → newRound → recordEvent → commit の独立API。commitは同一roundIdを二重受理しない。4096回分のID台帳が満杯なら「古いIDを消して再発行可」にはせず、明示的に拒否する実験用フェイルクローズ。持続する商用品にはデータ移行と拡張が必要。

**重要：永続保存は未実装。** 公式Roblox DataStoreService/UpdateAsyncによって、既存#275の所有/装備プロフィールとXP・熟練度・決済済roundIdをひとつのトランザクションとして永続化する製品版実装が必要。複数サーバーの同時ログアウトやタイムアウト、データロールバックも実機で確認するまで「保存可能」とは言わない。すでに持つキャラの誤消去防止を最優先にする。

**実機も未検証。** 正式採用には #220の唯一の統合担当がGameイベントへの接続、同一Gameサーバーへの統一、既存の試合結果とFREE孵化との同時実行、スマホUIと保存、2クライアント検証、H0/H1のFUN評価を行う。公式P0D進捗は最後に確認した75%で据え置き・FUN_GATE NO_GO・公開不可。

## 企画根拠

この企画の数値は初期**仮説**であり、実測継続率や売上予測ではない。Lv2達成率、2戦目選択率、実装後の孵化→装備→使用率、経験値の不正受取、Day1/Day7 継続率で判断して見直す。
