従来の1卵／5卵ゲーム、#288 v4の地面設置修正を含む中立兵8体＋精鋭1体・公平な復活予兆、拘束と救出、#285実レベルによるPvE/対人強化・2秒予兆8秒覚醒、#281 XP/熟練度、#282/#286孵化・所持・装備・同一DataStoreを維持。既存39本のうち35本はバイト同一で残し、Game/HUD/Store/Hordeのみ独立コピーで変更。#287原本EvolutionRulesをバイト完全同一で1本追加、合計 **40本、1つのServer Game / 1つのRemote**。

## 実装した実ゲーム機能
- 完全にサーバー検証された獲得イベント（卵の拾得・納品・防衛など）を試合終了時に既存のXPと同時決済し、進化素材を **1～2個／対象試合** 確定。二重決済、AFK、モブkill、クライアントが申告した獲得値は不採用。
- 孵化した本物の3魔獣に対し、**Lv10・魔獣熟練3・素材2 → 成長 Stage1、Lv25・熟練6・素材5 → 攻撃型/守護型 Stage2、Lv40・熟練10・素材10 → 神話 Stage3**。ロビーで装備中の本当の所持魔獣だけ進化。クライアントが送れるのは枝「攻撃／守護／指定不要」だけ。レベル、素材、アイテムID、要求IDはすべてサーバー所有。
- 旧schema1の保存データはそのまま、新しい任意の`evolution`フィールドを保存。既存XP・孵化・装備と同じ `U_<real UserId>` の1レコードへ **原子的UpdateAsync**。同じ試合receipt、進化requestIDの再送に対して素材の二重付与・二重消費を防止。破損時は元データを破壊せず拒否。
- 実際の保存データから現在の進化形態を読み、**既存の召喚済み魔獣モデルを成長拡大／色分岐／神話色へ変更**。Stage2+の攻撃魔獣は中立兵に12秒ごとにサーバー側で本物の範囲ダメージ（既存唯一のHorde.hitを使用、対人・城・卵への攻撃なし）。守護魔獣は召喚中最初8秒だけ、13stud範囲の味方への中立兵攻撃を最大3/5回まで無効化。両者は既存SCOUT召喚制限の範囲。PvP基礎倍率は#285以外に重ねない。
- ロビーで**🐉進化ボタン**を開くと専用モーダル（従来のモード・装備パネルは一時的に非表示）、素材/形態/必要条件/分岐を表示。既存の一つのHUD/Remote/シーケンスを利用。

## 留保
- **すべてStudio限定のDEVデータベースでの機能**。`RunService:IsStudio()` 制限は外していない。Studioで実UserId＞0かつAPI許可がない場合、進化と保存は拒否し、偽のLv/素材を表示しない。
- Roblox本番で永久保存できるとは未確認。DEV環境でも本当の再ログイン・競合・障害回復は人間の正規テストが必要。
- 原本#287の`actualCombatImplemented=false`は純ルールの設計値であり、このH1実ゲーム側が実3Dスキルの責任を持つ。原本は変更していない。
- 守護型は今回は**味方への中立NPC攻撃防御**。城のHP防護、味方対人PvP防護、職業進化、図鑑履歴と課金はまだ実装していない。
- UI・プレイヤー体験・FPS・複数client・Androidの検証は未実施。保護中の正式RC/独立原本/mainは非変更。勝てる面白さのOWNER評価待ち。
- #288 v4 Hordeの精鋭復帰時の予告キャンセルと、敵NPCと城HPの二重打撃防止を取り込む。v2の古い危険ソースは使わない。
