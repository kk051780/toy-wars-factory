## 実試合でのXP：サーバー事実からのみ
| 元のH1ゲームが本当に確定した行動 | XP | 1試合上限 |
|---|---:|---:|
| 正規の卵を取得（どちらのモードでも） | +10 | 2回 |
| 自陣の台に卵を納入（どちらのモードでも） | +25 | 2回 |
| 自分の罠が**卵を持った敵**に実際に発動 | +10 | 2回（DEFEND） |
| 所有・装備した3D魔獣が本当にサーバー生成され偵察を始めた | +12 | 1回（EQUIP_USE） |
| 正規試合終了 60〜360秒・上のうち卵の貢献あり | +50 | 1回 |
| 勝利時／引分時 | +15／+5 | 1回 |

最初の対戦で卵を1回拾い、60秒以上の正規試合を終えた場合、初期 Lv1→2（必要60 XP）の基準へ到達する。途中離席・0貢献・魔獣召喚だけでは試合終了XPは与えない。1試合の総受取は**最大150XP**、同じイベントID・種類別回数・同じ試合への再請求は純ルールとサーバー/保存レシートで拒否。対人への単なる攻撃/ダメージ/キルでは稼がない。原設計#281のRECOVER/ESCORTは本バージョンでは未接続であり、正規奪還・護衛を裏付けるサーバーイベントが固まってから独立レビューする。

## 保存・後方互換
前回DEV専用 DataStore `EGG_RUMBLE_PRIVATE_STUDIO_HATCH_DEV_V1` の同じユーザーキー U_<RealUserId> で、**所有・図鑑/装備・無料孵化レシートと、プレイヤーLv/残XP・魔獣ごとの熟練度・決済済み試合ID**を同じ `UpdateAsync` プロフィール内で更新する。従来のschema=1でprogressのないレコードは空のLv1進捗として後方互換に移行。旧所持品・装備・孵化レシートを壊さないよう正規化でprogressをコピーし、保存順序が競合しても原子的に更新する。
 - 試合IDはサーバーがGUID＋試合番号で付与。プレイヤーには渡さず、クライアントからXP値・レベル・対象・時刻・受取済IDを受け付けない。
 - Roblox本物のUserIdが1億を超える場合、#281純ルールだけが使う**内部計算ID**に変換。保存先の本物のUserIdとキーはそのまま使用し、アカウントごとの独立したRecord内でのみ計算IDを用いる。
 - `UpdateAsync` の競合コールバックは元データから毎回新しい `ProgressionRules` プロフィールと正規イベントを再構成。コールバックで乱数・yield・通信・GUI変更・プレイヤー操作はしない。
 - 保存応答なしの場合、HUDは `XP保存未確認`。成功応答した時だけ `XP保存応答`。**同じアカウントで再入室して本当に戻ることの検証は別条件。**
 - 原報酬レシートは2048件、XP決済試合IDは4096件まで**上限でフェイルクローズ**。古いIDを静かに捨てたり、重複で再獲得したりはしない。将来は移行設計・クォータ/レコードサイズ実測が必須。
