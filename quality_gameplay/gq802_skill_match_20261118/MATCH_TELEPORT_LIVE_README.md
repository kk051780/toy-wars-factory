## GQ802 Live local-cohort teleport bridge (added by successor on same #807 PR)
\nThis second code slice adds actual Roblox APIs in GQ802_MatchTeleportBridge.luau. It can call TeleportService:TeleportAsync with a server-generated ReservedServerId, store one match reservation in MemoryStoreHashMap:UpdateAsync, attach non-trusted teleport data, retry late failed teleports to the SAME reserved destination, and return to existing lobby on low population/Studio/missing ticket/network failure. It delegates all team fairness to existing GQ802 SkillMatchPolicy, and DOES NOT introduce any new RemoteEvent.\n\nOfficial Roblox 2026 docs: https://create.roblox.com/docs/projects/teleport-private-servers and https://create.roblox.com/docs/release-notes/release-notes-743 (ReserveServerAsync and ReservedServerAccessCode deprecated; new match uses GenerateGUID + ReservedServerId).\n\nIMPORTANT limits: this bridge only groups players currently in the SAME lobby server. Cross-lobby global matching needs separately reviewed MessagingService and queue coordination, and this module is opt-in DISABLED until existing Host wires an authorized call, verified real Studio/Roblox deployment and destination verifies claims using MemoryStore. Current code does not grant team/role/score privileges from TeleportData; this is an untrusted transport hint. Existing Host and Core36/41 untouched; OFF means code not loaded. Studio cannot test real TeleportAsync.\n\nNative mock tests simulate state, 8-person launch, source-only validated cohort, reserved ID, old-session retry, stale cleanup, tampering, no eligible people, wrong place, Studio disable and thrown network errors. No actual Teleport, Roblox production, live global server routing or official RC adoption is asserted.\n
