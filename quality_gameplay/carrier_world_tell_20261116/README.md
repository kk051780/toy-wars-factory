Server's **real** V3 \`session.rules.castles[id].heldEggs\` drives one world-space Billboard per human or AI carrier (1–3 eggs), at most 70 studs away, behind solid geometry, in TEAM/BR arenas. Polls every 0.3 sec; it normally updates on real egg-count changes, and also corrects stale cosmetic UI state. Does **not** change damage, rewards, scores, inventory, egg IDs, NPC actions or shop; only its own server-session cosmetic lifecycle flag is written. **Safety**: dead player, destroyed castle, zero eggs, empty actor, other match, match end, replay lobby or destroyed arena => no label. AI character replacement and human respawn delete stale labels; cleanup handles replay. Never infer egg possession from client attributes.

## Server-side optional emergency OFF switch (non-gameplay RC rollback)

Only a trusted server script sets `session.carrierWorldTellEnabled = false`. If false **before** `CarrierTell.start(session)`, no cosmetic loop or label starts; if changed to false during play, the next bounded 0.3-second polling cycle destroys all this session's labels and releases its single task. TEAM and BR flags are independent. The game continues with unmodified held eggs, HP, skills, neutral and item effects, rewards and lobby. To resume intentionally, the server sets the flag to true and calls `CarrierTell.start(session)` again. This switch is **never connected to a client Remote**, an arbitrary player Attribute or an administrative chat command. A code-free private composer rollback is removal of the two optional modules plus the two generated host hooks.

## Per-avatar fault containment — preserve all healthy egg carriers (2026-11-16)

The optional WorldTell poll previously caught one bad BotActor/visual API exception at the **entire session** level. That prevented source/gameplay corruption, but one faulty bot could blank 15 other healthy carrier badges in that mode. The fix wraps **each roster entry's cosmetic inspection** in its own yielding-safe Luau `pcall`. When one avatar is faulty, only that one avatar's badge is destroyed; the other healthy 15 TEAM carriers and 16 BR carriers continue displaying. Each faulty id gets **at most one diagnostic warning per continuous failure streak** (prevents 0.3-second log spam). The healthy avatar's marker reappears automatically when the visual dependency recovers, without restarting the whole session or creating duplicate labels. The original session-wide `pcall` still safely exits and cleans all records for true world-level faults. These exception handlers surround **our cosmetic code only**, never the original game Rules, HP, castle, AI combat, items, neutral horde or lobby.

The actual authored Luau module's native fault injection covers 16+16 concurrent seats, two consecutive broken/recovered episodes, one warning per episode, all 31 healthy badges remaining while one broken, and no leaked coroutines. In the combined real #482 `CastleMatchRules` native VM, the genuine source creates real egg tokens for one human and one AI, simulates that AI's visual failure, preserves the human badge, confirms original match `ACTIVE` and exact `auditEggConservation().valid == true`, then restores only the AI badge on recovery. No Studio client, Android FPS or visual readability is claimed.
